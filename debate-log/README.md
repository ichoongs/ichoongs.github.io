# 동아리 토론 기록실

아이패드에서 토론의 화자와 교사 관찰을 기록하는 정적 웹앱입니다. 설치나 외부 라이브러리 없이 HTML·CSS·JavaScript로 동작하며, 학생 정보와 기록을 외부 서버에 전송하지 않습니다. GitHub Pages에는 앱 코드만 올립니다.

## 토론 시작하기

1. 아이폰 음성 메모에서 녹음을 시작합니다.
2. 아이패드 음성 메모에서도 **별도로 녹음을 시작**합니다.
3. 아이패드 Safari의 기록실로 돌아옵니다. 웹앱은 음성 메모를 시작·종료하거나 녹음 상태를 확인하지 않습니다.
4. 주제·학생 이름·찬반 입장·좌석·태그를 확인합니다. 추가·삭제로 전체 인원을, 입장 선택으로 찬반 인원을 조정합니다. **찬반 좌우 바꾸기**로 교사가 보는 실제 좌석에 맞춰 두 편의 위치를 바꿉니다. 학생은 1~30명입니다.
5. **토론 기록 시작**을 누릅니다. 소리 없는 3초 카운트다운 후 **지금 박수!**에 맞춰 다 같이 한 번 박수를 칩니다. 이 화면 표시가 앱 경과 시간 0초입니다.
6. 학생이 발언할 때 학생 버튼을 누릅니다. 누른 즉시 발언 시작이 기록되며, 같은 학생을 다시 눌러도 새 구간이 생깁니다. 저장 버튼은 필요 없습니다.
7. 사회자가 진행·질문할 때는 **사회자**, 불분명한 구간은 **화자 불명**, 휴식·침묵 구간은 **발언 없음**으로 기록합니다. 사회자도 별도 발언 구간으로 저장되며 학생에게 자동 배정하지 않습니다. 경과 시간은 계속 갑니다.
8. **토론 종료** 후 두 기기의 음성 메모도 각각 종료·보관합니다. 기록실 종료 버튼은 음성 메모를 종료하지 않습니다.

Apple은 음성 메모 녹음 중 다른 앱을 사용할 수 있지만, 다른 앱이 기기에서 오디오를 재생하지 않아야 한다고 안내합니다. 이 앱에는 오디오 재생·마이크 사용 코드가 없습니다. [Apple의 iPad 음성 메모 안내](https://support.apple.com/en-au/guide/ipad/ipadf455678zz/26/ipados/26).

## 관찰·수정

- 태그는 현재 발언에 즉시 붙습니다. 다시 누르면 취소됩니다. 태그 추가 시각과 발언 시작 시각은 별도로 보관합니다.
- 메모는 입력을 시작한 발언에 연결됩니다. 작성 도중 다른 화자로 넘어가도 메모 대상은 바뀌지 않으며 입력란 아래에 표시됩니다. 입력 초안도 자동 저장합니다. **추가**를 누르면 관찰 기록이 됩니다.
- 직전 작업 취소는 발언·태그·메모·수정·단계 변경 등 최근 40개 작업을 되돌립니다. 종료를 취소하면 원래 시작 시각부터 시간축이 이어집니다.
- 최근 기록의 **수정**에서 화자·앱 시작 시각·단계·태그·메모를 수정합니다. 메모 내용을 비우면 해당 메모가 제거됩니다. 시간은 `00:00:12.350` 형식이며 기록은 시간순으로 정렬됩니다.
- 수정 창의 화자 목록에서도 **사회자**를 선택할 수 있습니다. 사회자 발언에는 태그·메모를 붙일 수 있고 CSV·JSON·텍스트에도 사회자로 표시됩니다.
- **전체 보기**에서 이전 발언도 수정합니다. 종료한 토론도 수정·내보내기가 가능합니다.
- 설정의 **찬반 좌우 바꾸기**, 또는 토론 중 **기록 관리 → 좌석 배치 → 찬반 좌우 바꾸기**로 좌우를 전환합니다. 학생의 찬반 입장·각 편의 학생 순서·발언 시각·관찰은 유지됩니다. 배치는 자동 저장되며 새로고침·JSON 백업·지난 토론·다음 토론에도 이어집니다. 오래된 백업은 찬성 왼쪽으로 열립니다.
- 기본 6명, 아이패드 11형 가로 화면에서 화자 버튼을 크게 배치했습니다. 인원·태그가 많거나 글자가 길면 세로 길이가 늘어납니다. 최근 목록은 내부에서 스크롤합니다.

## 박수로 녹음과 맞추기

**기록 관리 → 녹음과 시간 맞추기**에서 적용합니다.

```text
보정값 = 녹음에서의 박수 시작 시각 − 앱의 박수 기준 표시 시각
녹음상의 발언 시각 = 앱상의 발언 시각 + 보정값
```

예: 시작 박수가 아이폰 녹음의 8.250초, 앱 기준은 0초라면 `8.250`을 입력합니다. 이후 앱 30초에 시작한 발언은 녹음에서 38.250초입니다. 아이패드 녹음의 박수는 4.100초에 있을 수 있으므로, 그 파일을 사용할 때는 `4.100`으로 바꿔 다시 내보냅니다. 원래 발언 시각은 변하지 않습니다.

시작 박수를 놓쳤다면 진행 중 **3초 후 박수 기준 다시 표시**를 사용합니다. 표시한 앱 시각도 파일에 남습니다. 이 경우 해당 표시 시각을 빼서 보정값을 계산합니다. 박수는 화면을 보고 치므로 반응 시간만큼 작은 오차가 생길 수 있습니다. 여러 사람이 치더라도 한 번의 박수 시작점을 양쪽 녹음에서 같은 기준으로 골라 주세요. 앱은 박수를 감지하거나 두 기기를 자동 동기화하지 않습니다.

## 자동 저장·반복 사용·보존

- 현재 토론과 메모 초안: `localStorage`의 `debate-log.v1`.
- 지난 토론: 같은 브라우저의 IndexedDB `debate-log-library`. 종료한 토론은 자동 보관합니다. **보관하고 새 토론**은 현재 토론을 종료·보관한 뒤 학생·주제·태그 설정을 다음 토론에 이어줍니다.
- **지난 토론 보관함 → 삭제**로 불필요한 토론을 지울 수 있습니다. 제목·날짜를 확인하고 **토론 삭제**를 누르면 기기에서 발언·관찰 기록이 삭제됩니다. 삭제는 되돌릴 수 없으며 별도로 내보낸 파일은 그대로입니다. 현재 열린 종료 토론을 삭제하면 학생·주제·태그 설정을 유지한 새 토론 준비 화면으로 돌아갑니다. 진행 중인 현재 토론은 종료 후 삭제할 수 있습니다.
- **지난 토론 보관함 → 열기**로 다시 수정·내보내기를 이어갑니다. 백업 JSON을 불러올 때도 현재 토론을 먼저 종료·보관합니다.
- 경과 시간은 `현재 시각 − 시작 시각`으로 계산합니다. 화면 잠금·앱 전환·새로고침 후에도 실제 시간이 반영되며, 종료 후에는 `종료 시각 − 시작 시각`으로 고정합니다. 기기 날짜·시각을 수동으로 바꾸면 시간축에 영향을 줄 수 있습니다.
- 저장 실패는 화면 상단에 계속 표시합니다. 저장 재시도 또는 파일 내보내기가 가능합니다. 손상된 저장 자료는 자동으로 덮어쓰지 않고 원본 복구 파일 내보내기를 제공합니다.
- 다른 탭의 변경을 감지하면 오래된 탭의 쓰기를 막습니다. 하나의 탭에서 기록해 주세요.
- **기기 보관함은 영구 백업이 아닙니다.** 브라우저 데이터 삭제, 사생활 보호 브라우징, 기기 교체·분실 시 사라질 수 있습니다. 각 토론이 끝나면 JSON과 두 녹음 파일을 파일 앱·학교 보관 경로 등에 따로 저장하세요. 다른 브라우저·다른 도메인에는 현재 기록이 자동으로 옮겨지지 않습니다.

## 내보내기

| 형식 | 내용 |
|---|---|
| CSV | 발언 행과 관찰 행 분리, 원래 시각·보정 시각·관찰 추가 시각·단계·길이·태그·메모. 한글용 UTF-8 BOM 포함 |
| JSON | 학생·설정·시작/종료 시각·발언·관찰·단계·박수 기준·보정값·메모 초안. 백업 복원 가능 |
| 텍스트 | 전사 자료와 결합하기 쉬운 발언 타임라인, 태그·메모·단계·박수 기준 |

진행 중에도 내보낼 수 있으며, 마지막 발언의 길이는 내보낸 순간까지 계산합니다. CSV에는 아직 **추가**하지 않은 메모 초안은 들어가지 않습니다. 초안까지 보존하려면 JSON을 사용하세요. Safari에서 자동 다운로드가 시작되지 않으면 내보내기 아래에 나타나는 직접 다운로드 링크를 눌러 주세요.

CSV에서 `=`, `+`, `-`, `@` 등으로 시작하는 셀에는 작은따옴표를 붙여 표 계산 프로그램의 수식 실행을 방지합니다. JSON은 원문을 유지합니다. CSV·텍스트의 발언 종료 시각은 다음 발언 시작 또는 현재/최종 경과 시간으로 계산합니다. 발언이 없는 시작 구간은 첫 발언에 자동 배정하지 않습니다.

## GitHub Pages에 올리기

현재 배포 대상은 `ichoongs/ichoongs.github.io` 저장소의 `main` 브랜치, `debate-log/` 폴더입니다. 공개 앱 주소는 https://ichoongs.github.io/debate-log/ 입니다. 기존 사이트 파일을 유지하고 이 앱 폴더만 추가합니다. 아래는 별도 저장소에 독립 배포할 때의 방법입니다.

빌드가 필요 없으므로 다음이 가장 간단합니다.

1. 배포할 저장소의 루트에 이 폴더의 **내용물**을 올립니다. `index.html`, `core.js`, `app.js`, `vault.js`, `styles.css`, `icon.svg`, `.nojekyll`을 함께 올리세요. 실제 학생 기록 파일은 올리지 마세요.
2. 저장소 **Settings → Pages → Build and deployment → Source → Deploy from a branch**를 선택합니다.
3. `main`, `/ (root)`를 선택하고 저장합니다.
4. 표시되는 HTTPS 주소를 아이패드 Safari에서 엽니다. 저장소 하위 경로에서도 동작하도록 모든 자산 경로를 상대 경로로 작성했습니다.

GitHub Actions를 선호하면 동봉한 `.github/workflows/pages.yml`도 함께 올린 뒤, Pages의 Source에서 **GitHub Actions**를 선택하세요. 기본 브랜치가 `main`이 아니면 워크플로의 브랜치 이름을 맞추세요. 두 배포 방식 중 하나를 사용합니다. [GitHub 공식 Pages 설정 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

PC에서 미리 보려면 이 폴더에서 다음을 실행하고 브라우저로 `http://127.0.0.1:8766/`을 여세요.

```sh
python -m http.server 8766 --bind 127.0.0.1
```

로컬 Chrome UI에서 시작·연속 발언·태그·화자 전환 중 메모·수정·취소·새로고침 복구·종료 시간 고정·보관·주제/인원 변경·무음 카운트다운·박수 기준 시각을 확인했습니다. 다운로드 버튼 실행에는 JavaScript 오류가 없었습니다. 브라우저 자동화의 다운로드 완료 이벤트는 확인되지 않아, OS에 저장된 최종 파일 및 iPad Safari의 파일 저장은 아직 직접 확인하지 못했습니다. 파일 내용은 위 Blob 테스트로 검증했습니다.

실제 iPad Safari/음성 메모 조합에서는 다음을 한 번 확인하세요.

- [ ] 두 기기에서 녹음을 켜고 Safari로 전환해 30초 시험 녹음
- [ ] 무음 카운트다운에 맞춘 박수가 두 녹음에 모두 남음
- [ ] A → D → B를 연속 눌러 시각이 즉시 기록됨
- [ ] 태그·메모를 추가해도 발언 시작 시각이 유지됨
- [ ] 잠금·앱 전환·새로고침 뒤 경과 시간과 현재 화자 복구
- [ ] 종료 뒤 새로고침해도 최종 시간이 동일함
- [ ] CSV·JSON·텍스트가 파일 앱에 저장되고 한글이 보임
- [ ] JSON 복원, 새 토론, 지난 토론 다시 열기가 동작함

서비스 워커와 오프라인 캐시는 포함하지 않았습니다. 페이지를 처음 열거나 다시 불러올 때는 앱 파일을 가져올 연결이 필요합니다. 이미 열린 화면의 기록에는 서버 연결이 필요 없습니다. 녹음·AI 전사·세특 생성 기능은 포함하지 않았습니다.

## 향후 좌석 배치 검토

현재는 양쪽 대면 배치와 좌우 전환을 지원합니다. 학생의 찬반 입장과 화면의 좌석 위치는 별도로 보관합니다. 원탁은 다음 확장 때 교사의 위치를 기준으로 한 시계 방향 좌석 순서와 화면 회전을 검토하며, 이번 버전에는 구현하지 않았습니다.
